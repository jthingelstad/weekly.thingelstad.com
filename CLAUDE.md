## Architecture pattern — workshop-as-source

**`data/issues/{N}/archive.md` is the editorial source of truth.** Everything else regenerates from it:

- **workshop_bot** (`apps/workshop_bot/`) assembles each issue and ships three ways: email (Buttondown), website archive (this repo), audio (per-block TTS). Each `/eddy issue send` runs: `compose-archive` → `compose-transcript` → `render-audio` → POST/PATCH Buttondown → re-emit archive.md with `absolute_url` → atomic commit of `data/issues/{N}/*` to this repo's `main` via the GitHub Git Data API. Workshop runtime detail in [`apps/workshop_bot/CLAUDE.md`](apps/workshop_bot/CLAUDE.md).
- **`pipeline/content/content.py build`** reads `data/issues/{N}/{archive.md, metadata.json, links.json}` and writes `apps/site/archive/{N}.md` + `apps/site/_data/emails.json` with the 11ty front-matter contract (adds `layout`, `permalink`, `tags`, `audio_*`).
- **11ty** reads the generated `.md` files and renders the site; Pagefind indexes the built HTML post-build.

Edits land in `data/issues/{N}/archive.md`. **Never edit `apps/site/archive/*.md` directly** — they're regenerated and carry an inline `<!-- Generated by pipeline/content/content.py -->` notice. Body corrections, archive cleanup, broad editorial fixes all go in the canonical store.

Issues are committed by workshop_bot, not by an operator-side pull. If workshop_bot is down on publish day, the week skips — there's no recovery flow.

## Newsletter publishing eras — matters for any script that processes old issues

| Issues | Era | Platform | Body traits |
|---|---|---|---|
| #1–#41 | May 2017 – Feb 2018 | Tinyletter | Plain markdown, inline links, no structured sections, date stamps at the top |
| #42–#~130 | Mar 2018 – late 2019 | MailChimp | Templated headers, emoji-suffixed sections (`## Featured Links 🏅`, `## Notable Links 📌`, `## Yet More Links 🍞`); some issues plain-text with bare URLs |
| #~131 onward | 2020 – present | Buttondown | Canonical section names (`## Notable`, `## Featured`, `## Briefly`, `## Must Read`); H3-under-H2 link format `### [Title](url)` |

All bodies migrated forward into `data/issues/{N}/`. Link extraction in `librarian_core.links` (shared by the site build and workshop_bot's `compose-archive`) accepts the era-specific section names via `NOTABLE_SECTIONS` / `BRIEFLY_SECTIONS` sets — including the emoji variants.

## Link extraction — editorial links only

`librarian_core.links` extracts only curated links, not incidental references:

- **Notable** (`## Notable`, `## Must Read`, `## Featured`, emoji-suffixed variants): only H3 link headings (`### [Title](url)`). Inline links in commentary are ignored.
- **Briefly** (`## Briefly`, `## Recommended Links`, `## FYI`): only bolded links (`**[Title](url)**`).
- **Early issues** (no H2 structure): all links as fallback.

**Domain exclusion list**: `pipeline/content/domain_exclusions.py` (own domains, Buttondown, CDNs, URL shorteners, social, Wikipedia, YouTube). workshop_bot's `tools/avoid_domains.py` is a separate hand-maintained copy used for Pinboard pre-filtering — keep them loosely in sync; an exact match isn't required.

## Archive file front matter

`apps/site/archive/{N}.md` is generated; carries `layout`, `buttondown_id`, `number`, `subject`, `publish_date`, `slug`, `description`, `image`, `absolute_url`, `domains[]`, `links[]`, `word_count`, `permalink`, `tags`, plus `audio_*` fields injected from `data/audio/manifest.json`.

The `number` field determines the URL (`/archive/247/`). For Workshop-shipped issues, `/eddy issue start <N>` assigns; for migrated legacy issues, the number came from one-time backfill (subject-line parsing or auto-numbered by date).

Metadata corrections (subject, description, image, slug) edit the front matter in `data/issues/{N}/archive.md`. `data/issues/{N}/metadata.json` is a structured sibling for non-markdown consumers (status report, workshop_bot reads) — keep both in sync.

## Data files in `apps/site/_data/`

**Generated** (don't hand-edit):
- `emails.json` — lightweight metadata index. Written by `pipeline/content/content.py build`.
- `stats.json` — subscriber + Stripe figures. Written by `make stats` (`content.py stats`).
- `status.json` — pipeline state for `/ops/`. Written by `pipeline/status.py`.
- `voiceSamples.json` — home-page pull-quotes. Written by `pipeline/content/refresh_marketing_copy.py` (explicit `make refresh-copy`, not in CI).

**Hand-authored**:
- `site.json`, `support.json`, `quotes.json`, `survey.json`, `faq.json`, `redirects.json`. Edit these directly.

`archiveStats.js` is a JS data file that computes stats at build time from `emails.json` (records, streaks, per-year breakdowns).

## GitHub Actions — `.github/workflows/deploy.yml`

Triggered by push to main + manual `workflow_dispatch`. No cron, no webhook, no `repository_dispatch`. workshop_bot's ship-sequence commit triggers it via push.

Pipeline (in order): tests → stats refresh → audio (latest issue, `continue-on-error`) → archive build → corpus upload (`continue-on-error`) → Lambda deploy if changed → status snapshot → 11ty + Pagefind → auto-commit downstream artifacts → upload + deploy to GitHub Pages.

The `continue-on-error` steps shouldn't block a deploy — a TTS hiccup or Bedrock outage stays out of the critical path. Don't tighten those.

**Required GitHub Actions secrets** (kept in repo settings, not `.env`): `BUTTONDOWN_API_KEY`, `STRIPE_API_KEY`, `OPENAI_API_KEY`, `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY` (the `wt-archive` IAM user — needs S3 write to `weekly-thing-librarian` + `files.thingelstad.com`, CloudFront `CreateInvalidation` on `E3AEA6KRKI2B7E`, Bedrock `InvokeModel` on the embedding model).

## Conventions worth knowing

- **Python scripts that print progress** must reconfigure stdout to line-buffered. The default block-buffering hides progress when stdout is piped — see [`apps/workshop_bot/scripts/`](apps/workshop_bot/scripts/) for the pattern. (Memory: `feedback_unbuffered_output.md`.)
- **Subscriber count + Stripe balance** refresh via `make stats` (`pipeline/content/content.py stats`). `BUTTONDOWN_API_KEY` + `STRIPE_API_KEY` required. Don't hand-edit `apps/site/_data/stats.json`.
- **Pipeline name conventions** — entrypoint is `python pipeline/<area>/<name>.py`. The unified content entrypoint is `pipeline/content/content.py` with subcommands (`build`, `stats`, `publish`).
- **One-shot scripts retire to `pipeline/one-shot/`** when they finish their job. See that directory's README for the pattern — they're not deleted; they're kept as reference for similar problems later.
- **Buttondown email CSS** lives in `content/buttondown/newsletter/buttondown-email.css`. Paste into Buttondown's Custom CSS field. Uses system-font fallbacks (Charter, Iowan Old Style, SF Mono) because most email clients don't load remote fonts.
- **Test commands**: `make test` runs Python unit + Lambda tests. Workshop tests have their own: `make test-workshop` (no `.env`) or `make test-workshop-env` (with `.env` for runtime-config branches).
- **Stripe `locked_prefilled_email`** (not `prefilled_email`) on upgrade Payment Links so users can't break subscriber matching. (Memory.)
- **Buttondown newsletter `domain` field MUST stay empty** — setting it confirms a 404 on the custom-domain check. (Memory.)
- **CloudFront `E3AEA6KRKI2B7E`** fronts `files.thingelstad.com` (the public assets bucket). Audio uploads auto-invalidate; manual uploads need it too. (Memory.)
- **Pagefind UI** reset blocks CSS overrides — use `!important`. `data-pagefind-filter` survives until reindex. (Memory.)
- **Librarian deploy default** is `--skip-corpus-upload` for code-only deploys. Full reupload is slow + paid. (Memory.)
- **Tinylytics kudos** overwrites innerHTML — render heart/label via CSS `::before` so they survive. (Memory.)
